## 1. Executive Summary

`catnet` (`github.com/catnet-io/catnet`) is the official command-line interface for the CatNet network scanning ecosystem. It is engineered as a lightweight, scriptable utility designed for system administrators, security engineers, and CI/CD automated pipelines. The codebase strictly enforces a decoupled architecture: zero network scanning logic resides within this repository; all host discovery, ARP resolution, ICMP sweeps, and TCP port scanning are delegated to `github.com/catnet-io/engine`. The project is currently released at **v0.6.0** (released July 25, 2026), built on Go 1.26.5 without CGO dependencies.

Significant technical advances have been consolidated over recent cycles:
- Implementation of cross-platform distribution via GoReleaser v2 (Homebrew tap and Scoop bucket).
- Robust DevSecOps posture, including weekly SAST with `govulncheck` pinned to commit SHAs, `golangci-lint` verification, restricted `0600` file permissions for exported outputs, and cryptographic commit signature verification (`gpgsig`) for PRs merging into `main`.
- High test fidelity using an isolated subprocess test runner (`TestMain`) and an in-memory TCP mock listener, avoiding port collisions and preserving signal handling integrity (`SIGINT` / exit code 130).
- Automatic subnet discovery (`scan auto`) introduced in v0.6.0.

Despite strong engineering standards, critical operational and governance misalignments were identified:
1. **Overdue Milestones:** Milestone M5 (*Core Engine Alignment*, scheduled for 2026-08-04) and Milestone M6 (*Test Infrastructure*, scheduled for 2026-09-01) are both overdue.
2. **Documentation Inconsistency:** `docs/index.md` actively advertises a `--timeout` flag for `catnet scan`, but this flag is not implemented in the CLI codebase (Issue #44 remains open). Users attempting to run documented commands encounter `unknown flag: --timeout` (exit code 1).
3. **Stalled Dependency Updates:** A Dependabot PR (#86) updating `catnet-io/engine` from `v0.6.0` to `v0.7.0` has remained unreviewed and unmerged for over 30 days.
4. **Governance Single Point of Failure:** The repository operates with a *Bus Factor = 1*, dependent exclusively on a single maintainer.

**Preliminary Recommendation:** **Continue with adjustments**. The core technology is solid, but immediate action is required to resolve the documentation discrepancy, replan the overdue milestones, and merge the engine dependency update.

## 3. Factually Proven Findings

1. **Zero Scanning Logic in CLI:**
   - *Evidence:* `internal/cli/scan.go`, `internal/cli/export.go`, and explicit rules in `AGENTS.md`. All networking and scanning are imported from `github.com/catnet-io/engine`.
   - *Impact:* High architectural cohesion and low surface area for networking bugs in the CLI frontend.
   - *Confidence:* High.

2. **Documentation Defect (`--timeout` Flag):**
   - *Evidence:* `docs/index.md` (lines 51–62) lists `--timeout` under `catnet scan` options, but `internal/cli/scan.go` registers no such flag. Issue #44 ("feat: add --timeout flag to scan subcommand") remains open.
   - *Impact:* Confuses end users and breaks automated scripts copying documented usage.
   - *Confidence:* High.

3. **Expired Project Milestones:**
   - *Evidence:* GitHub Milestones API confirms Milestone 1 (M5) expired 2026-08-04 and Milestone 2 (M6) expired 2026-09-01.
   - *Impact:* Delays architectural alignment with `engine` async streaming.
   - *Confidence:* High.

4. **Stagnant Core Engine Dependency:**
   - *Evidence:* `go.mod` specifies `github.com/catnet-io/engine v0.6.0`, while PR #86 upgrading to `v0.7.0` has been open and pending since 2026-08-03.
   - *Impact:* Prevents `catnet` from benefiting from upstream optimizations and bug fixes.
   - *Confidence:* High.

5. **Strict Exit Code Contract:**
   - *Evidence:* Defined in `internal/cli/signals.go` (`0` Success, `1` Input Error, `2` Runtime Error, `130` Interrupted) and verified in `tests/integration_test.go`.
   - *Impact:* Ensures reliable predictability in CI/CD pipeline environments.
   - *Confidence:* High.

## 4. Hypotheses & Inferences

1. **Engine v0.7.0 Adoption Blocked by Upstream API Changes:**
   - *Hypothesis:* PR #86 may not have been merged because `v0.7.0` introduces API changes requiring refactoring in `internal/cli/scan.go`.
   - *Suggested by:* Open M5 milestone mentioning "Core Engine Alignment".
   - *Validation:* Test building `catnet` locally with `github.com/catnet-io/engine v0.7.0`.
   - *Impact if true:* Requires code modifications before PR #86 can merge.

2. **Windows Distribution Hindered by Antivirus False Positives:**
   - *Hypothesis:* Package manager distribution for Chocolatey and Winget (Issue #76) was deferred due to absence of an Authenticode code signing certificate.
   - *Suggested by:* Notes in Issue #76 regarding VirusTotal pre-submission and certificate requirements.
   - *Validation:* Check SmartScreen and VirusTotal scan results on `catnet.exe` binaries from v0.6.0 release.
   - *Impact if true:* Requires investment in digital signing certificates to achieve smooth Windows adoption.

3. **CLI Intended as Community Ingestion Layer for Desktop/Commercial Suite:**
   - *Hypothesis:* The CLI is deliberately kept MIT/free to drive awareness to `catnet-io/app` and prospective enterprise offerings.
   - *Suggested by:* Organization-level ecosystem tables listing `app`, `tui`, and `engine`.
   - *Validation:* Strategic alignment discussion with maintainers.
   - *Impact if true:* Business KPIs should track community adoption rather than direct CLI monetization.

## 5. Positive Architectural & Engineering Points

- **Clean Decoupling:** Complete delegation of scanning logic to `catnet-io/engine`.
- **Subprocess Integration Testing:** `TestMain` compiles the binary on the fly and tests execution via `os/exec`, eliminating global flag mutation issues.
- **Pipeline-First CLI Design:** Structured JSON streaming via `stdout`, progress bars and notices via `stderr`, automatic TTY detection for ANSI colors, and native `--quiet` mode.
- **DevSecOps Maturity:** `0600` output file permissions, signed commit enforcement on `main`, `govulncheck` scheduled workflows, and no local replace directives allowed in CI.
- **Strict Governance via `AGENTS.md`:** Well-defined guidelines prevent AI coding assistants from introducing regressions, breaking CI checks, or downgrading dependencies.

## 7. Scope & Roadmap Evaluation

- **Essential (MVP+):** `scan` (targets, ports, JSON/human output, quiet mode, timeout), `export` (JSON, CSV), `version`, exit codes contract.
- **Secondary:** `scan auto` (subnet auto-detection), XML export format.
- **Candidates for Deferral / Removal:**
  - `catnet serve` (Issue #56 — daemon REST API): Should be deferred. A REST server increases dependency bloat and security attack surface in what should remain a nimble CLI.
  - `catnet history` and `catnet diff` (Issue #55): Requires persistent storage engine; should only be considered after v1.0 core stability.
